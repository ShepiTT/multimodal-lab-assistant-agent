# 智能实验助手程序操作指导书

## 1. 文档用途

本文档用于说明“智能实验助手”程序的主要功能及操作方法，可作为“指导操作”知识库的入库文档，供系统在操作指导场景中检索和回答相关问题。

## 2. 系统简介

本程序是一个面向实验教学场景的多模态智能问答平台，支持以下核心功能：

- 文本问答与流式回复
- 语音识别与语音合成
- 图片识别与文档解析
- 知识库上传、构建与检索
- 场景化问答，包括操作指导、故障诊断、安全规范和代码调试
- 在线 IDE 代码执行与调试辅助

## 3. 启动程序

### 3.1 启动前准备

启动程序前，请确认以下环境已经安装或配置完成：

- Python 3.11 及以上版本
- 项目依赖已通过 `requirements.txt` 安装
- 已正确配置 `.env` 中的模型 API Key
- 如需使用代码执行功能，请确保 Docker 已安装并可正常运行

### 3.1.1 API 配置说明

本程序支持多种大模型、多模态模型、语音识别、OCR 和语音合成服务。启动前建议先在项目根目录的 `.env` 文件中配置对应的 API Key 和 Base URL。

#### 配置文件位置

API 配置文件通常位于项目根目录，文件名为 `.env`。如果项目根目录下还没有 `.env` 文件，可以参考 `.env.example` 手动创建一个。

推荐操作步骤如下：

1. 打开项目根目录。
2. 找到 `.env.example` 文件。
3. 复制一份并重命名为 `.env`。
4. 按照自己准备使用的模型服务填写 API Key 和 Base URL。
5. 保存后重新启动程序，使新配置生效。

#### 配置原则

配置时建议遵循以下原则：

- 只填写自己实际需要使用的服务，避免无关配置过多。
- 文本模型至少配置一种，否则普通问答功能无法正常使用。
- 如果需要图像理解或图片问答，需要额外配置多模态模型。
- 如果需要语音输入和语音播报，需要额外配置 ASR 和 TTS。
- 如果需要 OCR 识别图片文字或扫描文档，需要额外配置 OCR 服务。
- 如果希望减少外部 API 依赖，可以使用本地模型，但需要准备本地模型文件和推理环境。

#### 字段说明

每种远程模型配置通常由两部分组成：

- `API_KEY`：服务访问密钥，用于身份认证。
- `BASE_URL`：接口基础地址，用于指定模型服务调用入口。

对于百度语音和 OCR，一般还会包含额外字段：

- `SECRET_KEY`：与 `API_KEY` 配套使用的密钥。
- `TOKEN_URL`：获取访问令牌的地址。
- `ASR_URL`、`TTS_URL`：具体的语音识别或语音合成接口地址。

  - `DEEPSEEK_BASE_URL`

  - `ARK_API_KEY`

#### 多模态模型配置

- 通义千问多模态模型
  - `ALI_VL_API_KEY`
  - `ALI_VL_BASE_URL`
- 火山方舟豆包多模态模型
  - `ARK_API_KEY`
  - `ARK_BASE_URL`

#### 语音识别与语音合成配置

#### 本地模型配置

如果使用本地模型，一般不需要填写远程 API Key，但需要提前准备模型文件和本地推理环境。当前项目已支持本地文本模型、本地多模态模型、本地 ASR 以及本地 OCR。

#### 完整 `.env` 配置示例

以下示例适用于同时启用通义千问文本、多模态、百度语音、百度 OCR、DeepSeek 和豆包等服务的情况。实际使用时可以根据需要保留其中一部分配置。

```env
# 百度语音 API（ASR / TTS）
BAIDU_API_KEY=xxx
BAIDU_SECRET_KEY=xxx
BAIDU_TOKEN_URL=https://aip.baidubce.com/oauth/2.0/token
BAIDU_ASR_URL=https://vop.baidu.com/server_api
BAIDU_TTS_URL=https://tsn.baidu.com/text2audio

# 百度 OCR
BAIDU_OCR_API_KEY=xxx
BAIDU_OCR_SECRET_KEY=xxx

# 通义千问文本模型
ALI_API_KEY=sk-xxx
ALI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1

# 通义千问多模态模型
ALI_VL_API_KEY=sk-xxx
ALI_VL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1

# DeepSeek
DEEPSEEK_API_KEY=sk-xxx
DEEPSEEK_BASE_URL=https://api.deepseek.com

# 火山方舟豆包
ARK_API_KEY=xxx
ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3

# OpenAI（可选）
OPENAI_API_KEY=sk-xxx
OPENAI_BASE_URL=https://api.openai.com/v1

# 本地 LLM（如有）
LOCAL_LLM_BASE_URL=http://127.0.0.1:8000/v1
LOCAL_API_KEY=local-key
```

#### 最简配置示例

如果当前只需要先把系统跑起来，并完成最基本的文本问答，推荐先使用最简配置。例如只配置通义千问文本模型：

```env
ALI_API_KEY=sk-xxx
ALI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

如果想同时支持文本问答和图片理解，可增加：

```env
ALI_VL_API_KEY=sk-xxx
ALI_VL_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

如果还需要 OCR 与语音功能，再继续补充百度 OCR 和百度语音相关字段即可。

### 3.1.4 模型切换操作方法

程序支持在界面中切换不同模型提供商和具体模型。通常操作步骤如下：

1. 打开系统首页。
2. 在模型选择区域选择“模型提供商”。
3. 在对应下拉框中选择具体模型名称。
4. 输入问题并发送测试。
5. 如果当前模型返回异常，可切换到其他提供商再次测试。

#### 常见切换方式

- 文本问答：
  - 通义千问 `qwen-flash`
  - DeepSeek `deepseek-chat`

- 图片问答：
  - 通义千问 `qwen-vl-plus`
  - 豆包视觉 `doubao-seed-1-6-vision-250815`
  - 本地多模态 `local-qwen2-vl-2b`
- 语音识别：
  - 百度 `baidu-asr-v1`
  - 本地 `funasr-paraformer`
- OCR：
  - 百度 `baidu-ocr-general`
  - PaddleOCR `paddleocr-ch`
  - Tesseract `tesseract-chi-sim`

#### 什么时候需要切换模型

以下场景建议切换模型：

- 当前模型返回速度过慢
- 当前模型 API 未配置或额度不足
- 当前任务需要图像理解，但文本模型无法处理图片
- 当前希望使用本地模型，减少远程 API 调用
- 当前语音或 OCR 服务不可用，需要切换到备用方案

### 3.1.5 推荐配置方案

为了方便不同使用需求下的快速部署，下面给出几种推荐配置方案。

#### 方案一：基础问答方案

适用场景：只需要完成文本问答和基本知识库检索。

推荐配置：

- 文本模型：通义千问 `qwen-flash`
- `.env` 只配置：

  - `ALI_BASE_URL`

优点：

- 配置最简单
- 启动快
- 足以完成大部分文本问答测试

#### 方案二：多模态完整方案

适用场景：需要文本问答、图像理解、OCR、语音识别和语音合成全部可用。

推荐配置：

- 文本模型：`qwen-flash`
- 多模态模型：`qwen-vl-plus`
- OCR：`baidu-ocr-general`
- ASR：`baidu-asr-v1`
- TTS：`baidu-tts-female`

建议 `.env` 配置：

- `ALI_API_KEY`
- `ALI_BASE_URL`
- `ALI_VL_API_KEY`
- `ALI_VL_BASE_URL`
- `BAIDU_API_KEY`
- `BAIDU_SECRET_KEY`
- `BAIDU_OCR_API_KEY`
- `BAIDU_OCR_SECRET_KEY`

优点：

- 功能覆盖完整
- 适合展示系统全部能力
- 适合毕业设计答辩演示

#### 方案三：本地优先方案

适用场景：希望减少远程 API 依赖，优先使用本地模型。

推荐配置：

- 文本模型：`local-qwen3-1.7b`
- 多模态模型：`local-qwen2-vl-2b`
- OCR：`paddleocr-ch` 或 `tesseract-chi-sim`
- ASR：`funasr-paraformer`
- TTS：`system-tts`

注意事项：

- 需要本地模型文件完整
- 需要足够的显存和本地推理环境
- 首次加载模型速度可能较慢

#### 方案四：调试与备用方案

适用场景：主模型不可用时快速切换。

推荐做法：

- 主用：通义千问 `qwen-flash`
- 备用：DeepSeek `deepseek-chat`
- 第二备用：豆包 `doubao-seed-1-6-251015`
- 本地兜底：`local-qwen3-1.7b`

这种配置有利于在某一家服务异常时快速切换，不影响系统演示和日常使用。

### 3.1.6 常见配置错误与排查方法

#### 错误一：填写了 API Key 但模型仍不可用

可能原因：

- Base URL 填写错误
- `.env` 文件未保存
- 程序未重启，导致新配置未加载

处理方法：

1. 检查 `.env` 文件内容是否正确。
2. 检查是否多输入空格或引号。
3. 保存后重新启动程序。

#### 错误二：图像问答不可用

可能原因：

- 只配置了文本模型，没有配置多模态模型
- 上传图片后调用的仍是纯文本模型

处理方法：

1. 配置 `ALI_VL_API_KEY` 和 `ALI_VL_BASE_URL`，或其他多模态模型。
2. 在界面中确认当前选择的是多模态模型。

#### 错误三：语音识别不可用

可能原因：

- 未配置百度语音识别的 Key
- 本地音频转换依赖不可用

处理方法：

1. 检查 `BAIDU_API_KEY` 和 `BAIDU_SECRET_KEY`。
2. 检查 `ffmpeg` 是否安装。
3. 尝试切换到本地 ASR。

#### 错误四：OCR 无法识别

可能原因：

- 百度 OCR 未配置
- 本地 OCR 依赖未安装
- 上传图片格式不支持

处理方法：

1. 检查 OCR 配置项。
2. 尝试切换到 PaddleOCR 或 Tesseract。
3. 使用 JPG、JPEG、PNG 等常见格式重新测试。

#### 错误五：火山引擎配置后界面读取异常

当前项目配置文件中使用的标准字段是 `ARK_BASE_URL`。在部分环境读取逻辑中也可能看到 `APK_BASE_URL` 字段名称，因此实际配置时建议优先填写：

- `ARK_API_KEY`
- `ARK_BASE_URL`

如果前端环境信息读取异常，可同时检查相关配置项是否一致。

## 4. 基础问答操作

### 4.1 文本问答

1. 在输入框中输入问题。
2. 选择模型提供商与具体模型。
3. 点击发送按钮。
4. 等待系统返回回答内容。

### 4.2 流式输出

系统支持流式回复。启用后，模型回答会逐步显示，适合观察长文本生成过程。

### 4.3 历史会话

系统会自动保存会话历史。用户可以：

- 创建新会话
- 查看历史对话
- 删除指定会话

## 5. 语音功能操作

### 5.1 语音输入

1. 点击录音按钮。
2. 允许浏览器访问麦克风。
3. 录制完成后上传音频。
4. 系统自动执行语音识别并返回文本结果。

### 5.2 语音输出

1. 输入问题并获取模型回答。
2. 调用语音合成功能。
3. 系统将文本转换为音频并返回可播放文件。

## 6. 文件上传与文档解析

### 6.1 支持的文件类型

系统支持以下文件：

- 文本文档：TXT、MD、CSV、JSON
- 办公文档：DOCX、PDF、XLSX
- 图片文件：JPG、JPEG、PNG
- 代码文件：PY、JS、JAVA、CPP 等

### 6.2 上传并解析文件

1. 在文件上传区域选择本地文件。
2. 点击上传。
3. 系统自动判断文件类型并调用对应解析器。
4. 解析成功后，文件内容可用于问答或知识库构建。

### 6.3 文件问答

上传文件后，用户可直接针对文件内容提问，系统会结合解析结果进行回答。

## 7. 指导操作知识库入库方法

本节用于说明如何将“程序操作指导文档”加入指导操作知识库。

### 7.1 上传知识文档

1. 进入知识库管理相关界面。
2. 选择知识库类型为“指导操作”。
3. 上传操作指导类文档，例如本文件《智能实验助手程序操作指导书》。
4. 上传完成后，系统会将文件保存到 `knowledge_base/operating_instructions/data` 目录。

### 7.2 构建知识库索引

1. 上传完成后，点击“构建索引”。
2. 选择切分方式，推荐使用 `smart`。
3. 默认切分大小可设置为 `500`。
4. 等待系统完成切分、向量化和索引构建。

### 7.3 检查入库结果

入库完成后，可通过以下方式确认：

- 在知识库文件列表中看到已上传文件
- 在知识库状态页面查看索引是否已构建
- 使用检索测试功能输入相关问题，检查是否能够召回本文件内容

## 10. 常见问题

### 10.1 Docker 未启动

现象：代码执行功能不可用。

处理方法：

1. 检查 Docker 是否已安装。
2. 启动 Docker Desktop。
3. 重新打开系统并检查 Piston 是否正常运行。

### 10.2 知识库构建失败

现象：上传文档后无法完成索引构建。

处理方法：

1. 检查上传文件格式是否受支持。
2. 检查 Embedding 模型和依赖是否正常加载。
3. 检查知识库目录下是否存在有效文件。

### 10.3 模型无法回答

现象：发送问题后没有返回正常结果。

处理方法：

1. 检查 API Key 是否配置正确。
2. 检查当前模型服务是否可用。
3. 尝试切换其他模型提供商。
